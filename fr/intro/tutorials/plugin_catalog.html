De l’idée au catalogue de plugins#

Ce tutoriel montre comment transformer une idée en un plugin accessible à tous les utilisateurs de DataLab : nous créons un plugin en un seul fichier Python, l’essayons dans DataLab, puis le publions dans le catalogue de plugins DataLab, depuis lequel les utilisateurs l’installent en quelques clics. Ni projet de packaging ni compte PyPI ne sont nécessaires.

À titre d’exemple, nous écrivons un plugin « Spectrum Tools », dont le traitement met à zéro les valeurs négatives d’un signal. Remplacez-le par votre propre idée : un traitement propre à votre domaine, un format de fichier, une analyse…

Prérequis#

  • DataLab installé en tant que paquet Python, par exemple avec pip install datalab-platform (voir Installation) : la commande datalab-plugin utilisée ci-dessous n’est pas fournie par la version autonome de DataLab ;

  • un compte GitHub, pour publier le code source du plugin et le proposer au catalogue.

Étape 1 : créer le plugin#

Créez le plugin avec la commande datalab-plugin. L’option --github-account dérive l’identifiant du plugin de votre compte GitHub, ici alice, comme l’attend le catalogue :

datalab-plugin create --name "Spectrum Tools" --description "Spectral processing tools for DataLab" --github-account alice

La commande écrit le fichier datalab_spectrum_tools.py dans le répertoire des plugins utilisateur (voir Où est positionné un plugin ?) et affiche son emplacement. Le début du fichier déclare l’identité du plugin :

PLUGIN_DESCRIPTION = "Spectral processing tools for DataLab"
PLUGIN_ID = "io.github.alice.spectrum-tools"
PLUGIN_NAME = "Spectrum Tools"

Sa version, 0.1.0, est donnée par l’attribut PLUGIN_INFO de la classe du plugin. Ne modifiez plus l’identifiant du plugin une fois celui-ci publié : DataLab et le catalogue l’utilisent pour identifier le plugin.

Étape 2 : essayer et développer le plugin#

Démarrez DataLab, ou sélectionnez Plugins > Recharger les plugins s’il est déjà lancé. Dans le panneau des signaux, le menu Plugins contient alors un sous-menu Spectrum Tools, avec une action Sample processing. Créez un signal avec Création > Sinus, gardez-le sélectionné, et lancez cette action : elle ajoute un nouveau signal, dont les valeurs négatives sont mises à zéro.

Ouvrez le fichier dans votre éditeur. Le traitement est la fonction sample_processing, qui reçoit les valeurs Y du signal sélectionné sous forme de tableau NumPy et en renvoie de nouvelles :

def sample_processing(y: np.ndarray) -> np.ndarray:
    """Return new Y values computed from those of the selected signal.

    Edit this function to implement your own processing.
    """
    return np.maximum(y, 0.0)

Implémentez votre propre traitement, donnez à l’action un titre explicite dans la méthode register_computations, puis sélectionnez Plugins > Recharger les plugins pour essayer vos modifications, sans redémarrer DataLab. Pour aller plus loin (paramètres de traitement, images, formats de fichiers…), voir Développer des plugins, et prenez exemple sur les plugins du catalogue (voir Plugins du catalogue).

Étape 3 : partager le fichier avec vos collègues#

Le plugin peut déjà être utilisé par d’autres : envoyez-leur le fichier. Ils l’installent avec Plugins > Configurer les plugins… > Depuis un fichier (voir Onglet Depuis un fichier), y compris dans la version autonome de DataLab.

Étape 4 : publier le code source sur GitHub#

Créez un dépôt GitHub public, par exemple datalab-spectrum-tools, contenant :

  • le fichier datalab_spectrum_tools.py ;

  • un fichier LICENSE, avec une licence open source approuvée par l’OSI, comme BSD-3-Clause ou MIT (le guide de contribution du catalogue liste les licences acceptées) ;

  • un fichier README.md, décrivant ce que fait le plugin et comment l’utiliser.

Créez ensuite une release du dépôt, avec le tag v0.1.0 correspondant à la version du plugin, et joignez-y le fichier datalab_spectrum_tools.py inchangé. Avec la GitHub CLI, depuis le dossier du dépôt :

gh release create v0.1.0 datalab_spectrum_tools.py --title "Spectrum Tools 0.1.0" --notes "First release"

Conservez le même nom de fichier pour toutes les versions : n’y ajoutez pas le numéro de version.

Étape 5 : proposer le plugin au catalogue#

Créez un fork du dépôt du catalogue et ajoutez un fichier plugins/io.github.alice.spectrum-tools.yaml, nommé d’après l’identifiant du plugin :

id: io.github.alice.spectrum-tools
name: Spectrum Tools
kind: module
summary: Spectral processing tools for DataLab
license: BSD-3-Clause
repository: https://github.com/alice/datalab-spectrum-tools
capabilities: [processing]
keywords: [spectroscopy, spectrum]
releases:
  - version: "0.1.0"
    filename: datalab_spectrum_tools.py
    sha256: <SHA-256 digest of the released file>
    requires_python: ">=3.10"

kind: module indique que le plugin est un simple fichier Python : le catalogue propose de tels plugins à DataLab Desktop. L’identifiant et la version doivent concorder avec ceux du fichier ; le catalogue affiche le nom indiqué dans le fichier YAML. Le champ sha256 donne l’empreinte du fichier joint à la release ; vous pouvez la calculer avec sha256sum datalab_spectrum_tools.py sous Linux et macOS, ou avec Get-FileHash datalab_spectrum_tools.py dans Windows PowerShell (en minuscules). Si vous l’omettez, la première exécution des vérifications automatiques échoue et affiche la ligne à ajouter.

Ouvrez ensuite une pull request. Ses vérifications automatiques téléchargent le fichier depuis la release, vérifient son empreinte et l’inspectent sans l’exécuter : nom du fichier, syntaxe Python, identité et version du plugin, licence. Les mainteneurs du catalogue vérifient ensuite que le plugin correspond à sa description ; cette revue n’est pas un audit de sécurité.

Étape 6 : votre plugin est dans le catalogue#

Une fois la pull request fusionnée, le catalogue est publié à nouveau : le plugin apparaît sur la page du catalogue de plugins DataLab, avec la mention Community, et dans l’onglet Catalogue de la boîte de dialogue Plugins > Configurer les plugins…, depuis lequel les utilisateurs de DataLab l’installent en un clic (voir Onglet Catalogue).

Pour publier une nouvelle version, augmentez la version dans le fichier, créez une nouvelle release (par exemple v0.2.0) contenant le fichier sous le même nom, puis ajoutez cette version, avec son empreinte, à la fin de la liste releases du fichier YAML, dans une nouvelle pull request. L’onglet Catalogue propose alors aux utilisateurs de mettre à jour le plugin.

Plugins plus importants

Pour un plugin composé de plusieurs modules, avec des ressources, des tests ou des dépendances, créez un projet structuré en couches avec datalab-plugin create --project (voir Créer un projet de plugin structuré en couches). Son workflow de release construit le wheel du plugin lorsque vous poussez un tag de version, le joint à une release GitHub avec son empreinte SHA-256, et affiche l’entrée à soumettre au catalogue. Un wheel peut aussi déclarer une classe de plugin DataLab-Web distincte dans le groupe de points d’entrée datalab.web_plugins, afin que le plugin soit proposé aux utilisateurs des deux éditions (voir Plugins et DataLab-Web).
