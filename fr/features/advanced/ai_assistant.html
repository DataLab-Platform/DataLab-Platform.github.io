Assistant IA#

DataLab intègre un assistant IA optionnel : un panneau de discussion ancrable, connecté à un grand modèle de langage (LLM), capable d’inspecter votre espace de travail, de créer et de traiter des signaux et des images, et d’écrire puis d’exécuter des macros Python à votre place.

Avertissement

L’assistant IA transmet vos messages — et, lorsque vous le lui demandez, des informations sur les objets de votre espace de travail — au fournisseur configuré. Rien n’est envoyé tant que l’assistant est désactivé ou tant que vous n’avez pas démarré de conversation. Consultez la section Confidentialité et sécurité avant d’utiliser un fournisseur distant sur des données sensibles.

Premiers pas#

  1. Ouvrez Fichier > Préférences, allez dans l’onglet Assistant IA et activez l’assistant (voir Assistant IA pour la liste complète des options).

  2. Choisissez un fournisseur et un modèle, puis renseignez la clé d’API — ou, de préférence, laissez le champ vide et définissez la variable d’environnement standard du fournisseur.

  3. Cliquez sur Tester la connexion pour vérifier le point d’accès avant de commencer.

  4. Affichez le panneau Assistant IA depuis le menu Affichage s’il est masqué. Il est ancré sur le côté droit de la fenêtre principale, en onglet avec le panneau de macros.

Astuce

Pour découvrir l’assistant sans compte ni clé d’API, sélectionnez le fournisseur mock : il répond par des réponses scriptées déclenchées par de simples mots-clés, et met en œuvre toute la chaîne de traitement (appels d’outils, boîtes de dialogue de confirmation, stockage des conversations) hors ligne.

Fournisseurs pris en charge#

L’assistant dialogue avec tout service exposant une API de complétion de conversation compatible OpenAI. Cela couvre notamment :

  • OpenAI (https://api.openai.com/v1)

  • GitHub Models (https://models.github.ai/inference)

  • Azure OpenAI

  • Des environnements d’exécution locaux tels que Ollama, LM Studio, llama.cpp ou vLLM

Le bouton Charger un préréglage… de la boîte de dialogue des préférences pré-remplit les champs URL de base et Modèle pour les points d’accès les plus courants.

Utilisation du panneau de discussion#

Le panneau se compose d’une barre d’outils, de la vue de conversation et d’une zone de saisie :

  • Nouvelle conversation : démarrer une nouvelle conversation. La précédente est conservée dans l’espace de stockage des conversations.

  • Historique… : parcourir les conversations passées, les charger, les renommer ou les supprimer, et en exporter une au format Markdown. Les conversations sont stockées dans le répertoire de configuration utilisateur de DataLab.

  • Envoyer / Arrêter : envoyer le message courant, ou interrompre une requête en cours. Les requêtes s’exécutent dans un fil d’exécution en arrière-plan, si bien que l’interface reste réactive.

  • Le compteur de jetons à droite de la barre d’outils indique la taille du contexte de la dernière requête et la consommation cumulée de la conversation.

La zone de saisie conserve un historique des messages précédemment envoyés, navigable au clavier comme dans un terminal.

Lorsque l’assistant propose une macro, le code généré est temporaire : il est exécuté sans encombrer le panneau de macros. Un lien Enregistrer dans les macros est proposé après l’exécution si vous souhaitez la conserver.

Outils à la disposition de l’assistant#

L’assistant n’agit pas directement sur DataLab : il ne peut appeler qu’un ensemble fixe d”outils déclarés. Les outils marqués comme étant en lecture seule ne modifient jamais l’espace de travail et peuvent être approuvés automatiquement (voir l’option correspondante) ; tous les autres outils exigent une confirmation explicite.

Confirmation des appels d’outils#

Chaque fois que l’assistant souhaite exécuter un outil modifiant l’espace de travail, une boîte de dialogue de confirmation affiche le nom de l’outil et la valeur des paramètres. Lorsqu’une macro est proposée, la boîte de dialogue affiche également son code source avec coloration syntaxique, afin que le code puisse être relu avant d’être exécuté. Refuser l’appel renvoie ce refus au modèle, qui peut alors proposer autre chose.

Confidentialité et sécurité#

  • Aucune télémétrie : DataLab n’enregistre ni ne transmet le contenu de vos conversations ailleurs qu’au fournisseur que vous avez configuré.

  • Fournisseurs locaux : pour que tout reste sur votre machine, faites pointer l”URL de base vers un environnement d’exécution local (Ollama, LM Studio, llama.cpp, vLLM). Les données ne quittent alors jamais votre ordinateur.

  • Stockage de la clé d’API : la clé est stockée en clair dans le fichier de configuration de DataLab. Préférez la variable d’environnement du fournisseur.

  • Confirmation explicite : toute action modifiant l’espace de travail — et toute exécution de macro — exige par défaut une confirmation explicite de l’utilisateur.

  • Limite d’itérations : le nombre d’appels d’outils enchaînés est borné par l’option Nombre maximum d’itérations d’appels d’outils, de sorte qu’un modèle défaillant ne puisse pas boucler indéfiniment.
