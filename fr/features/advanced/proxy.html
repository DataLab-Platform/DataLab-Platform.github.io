Objets proxy (datalab.control.proxy)#

Le module datalab.control.proxy permet d’accéder aux fonctionnalités de DataLab à partir d’une classe proxy.

Proxy distant#

Le proxy distant est utilisé lorsque DataLab est lancé dans un processus différent de celui du proxy. Dans ce cas, le proxy se connecte au serveur XML-RPC de DataLab.

class datalab.control.proxy.RemoteProxy(autoconnect: bool = True)[source]#

Classe proxy distante de DataLab.

Cette classe donne accès aux fonctionnalités de DataLab à partir d’une classe proxy. Il s’agit de la version distante du proxy, utilisée lorsque DataLab est lancé dans un processus différent de celui du proxy.

Paramètres:

autoconnect – Se connecter automatiquement au serveur XML-RPC de DataLab.

Lève:

  • ConnectionRefusedError – Impossible de se connecter à DataLab

  • ValueError – Délai d’attente invalide (doit être >= 0.0)

  • ValueError – Nombre de tentatives invalide (doit être >= 1)

Exemples

Voici un exemple simple d’utilisation de RemoteProxy dans un script Python ou un notebook Jupyter :

>>> from datalab.control.proxy import RemoteProxy
>>> proxy = RemoteProxy()
Connecting to DataLab XML-RPC server...OK (port: 28867)
>>> proxy.get_version()
'1.0.0'
>>> proxy.add_signal("toto", np.array([1., 2., 3.]), np.array([4., 5., -1.]))
True
>>> proxy.get_object_titles()
['toto']
>>> proxy["toto"]  # from title
<sigima.objects.signal.SignalObj at 0x7f7f1c0b4a90>
>>> proxy[1]  # from number
<sigima.objects.signal.SignalObj at 0x7f7f1c0b4a90>
>>> proxy[1].data
array([1., 2., 3.])
>>> proxy.set_current_panel("image")

Essayer de se connecter au serveur XML-RPC de DataLab.

Paramètres:

Gestionnaire de contexte de proxy#

Le gestionnaire de contexte de proxy permet de gérer facilement la création et la destruction du proxy. Il s’utilise comme suit :

with proxy_context("local") as proxy:
    proxy.add_signal(...)

Le type de proxy peut être « local » ou « remote ». Pour un proxy distant, le port peut être précisé sous la forme « remote:port ».

Note

Le gestionnaire de contexte permet d’utiliser le proxy dans différents contextes (script Python, notebook Jupyter, etc.). Il permet également de passer facilement du proxy local au proxy distant, tout en conservant le même code à l’intérieur du contexte.

datalab.control.proxy.proxy_context(what: str) → Generator[LocalProxy | RemoteProxy, None, None][source]#

Gestionnaire de contexte gérant la création et la destruction d’un proxy DataLab.

Paramètres:

what – Type de proxy (« local » ou « remote »). Pour un proxy distant, le port peut être précisé sous la forme « remote:port »

Produit:
proxy

LocalProxy si what == « local », RemoteProxy si what == « remote » ou « remote:port »

Exemple

with proxy_context(« local ») as proxy:

proxy.add_signal(…)

Appeler les méthodes des processeurs à l’aide d’objets proxy#

Tous les objets proxy donnent accès aux méthodes de calcul de DataLab exposées par les classes de processeurs :

  • datalab.gui.processor.signal.SignalProcessor

  • datalab.gui.processor.image.ImageProcessor

Pour exécuter une fonctionnalité de calcul associée à un processeur, vous pouvez utiliser la méthode calc() de l’objet proxy :

# Call a method without parameter
proxy.calc("average")

# Call a method with parameters
p = sigima.params.MovingAverageParam.create(n=30)
proxy.calc("moving_average", p)
